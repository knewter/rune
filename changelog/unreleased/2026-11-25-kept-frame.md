- **A frame that changes a small part of a window draws only that part.** A window now keeps its last frame in a texture of its own and works out, from the instances `prepare` already compares, which pixels a frame changed: each changed instance's quad, or the composite of the outermost isolated layer around it. While that is a small area, the frame clears it as a whole frame's pass does, draws it again under a scissor with only the layers that can show there, and copies the kept frame to the drawable. A 16-point looping mark in a 1440×900 window (`cargo run -p rune --example loop_mark`) went from clearing and shading the whole window every frame to clearing and shading a few thousand pixels around the mark: on lavapipe the rasterizer's time per frame fell from about 40 ms to about 2 ms, with every pixel the same as a whole frame's. Anything the instances don't say (glyph and image uploads, effect slots, backdrop blurs, native video surfaces, GPU springs, a new size, blend mode or clear colour) draws the frame whole, as does a change over half the window; after three whole frames in a row the window draws straight into the drawable again and lets the kept frame go. A window whose drawable can't be copied into (`COPY_DST`) draws as before. No API change.
